About

I write software for networks that do not depend on the regular internet and for servers that should be hard to break. Most of my work sits around Reticulum, the cryptography-based mesh networking stack. I maintain a Go implementation of the stack, a browser, a terminal client, a messaging app, a bot framework and a Micron parser, all developed in the open under Quad4.

The second thread is hardening. Landlock and seccomp bindings, signed releases, rootless containers and Firecracker microVMs show up across the projects. I also report vulnerabilities upstream and send fixes to the projects I depend on.

Development happens over Reticulum first through rngit, with mirrors on GitHub, CodeFloe and our own Forgejo fork. Commits are signed and the sites ship with no trackers.

Security work

Vulnerability reports, hardening patches and sandboxing libraries.

Navidrome: SQL injection via the artist role parameter
HighCVSS 8.8CWE-89GHSA-hm54-32q6-3rcrFixed in 0.64.0

Any authenticated user could inject SQL into the artist list query through the role parameter when sorting by song count, album count or size. That allows reading or changing anything in the database, including other users' data and stored secrets. Reported through GitHub private security advisories, independently of another researcher, and fixed upstream in Navidrome 0.64.0 on 12 September 2026. It is the same bug family as the earlier CVE-2025-48949 on a code path that fix did not cover.
